# 4.2.1 Levantamento de Requisitos

## Como os requisitos foram levantados

Os requisitos do BiblioTech foram levantados em três passos. Primeiro, uma **entrevista** com a Dona Marli, bibliotecária do campus e cliente do sistema, sobre como o empréstimo funciona hoje. Depois, uma **conversa curta** com o Pedro, estudante que usa a biblioteca toda semana, para ouvir o lado de quem pega o livro. Por fim, a **análise de um documento**: o caderninho em que a Dona Marli anota quem levou o quê.

O que está entre aspas na tabela a seguir foi dito por eles. A coluna da necessidade é interpretação minha, e foi lida de volta para a Dona Marli antes de virar requisito.

❓ **A confirmar com a cliente:** a Dona Marli não disse quantos dias dura um empréstimo. Adotei sete dias para seguir com a análise, e a pergunta fica anotada aqui.

## Da fala à necessidade

| # | Fala | O que é | Necessidade por trás |
|---|---|---|---|
| F1 | "Eu queria um sistema com uma telinha bonita mostrando o acervo" (Dona Marli) | solução | o leitor saber se o livro está disponível sem perguntar a ninguém |
| F2 | "Todo dia alguém vem perguntar se tal livro está na estante" (Dona Marli) | necessidade | consulta de disponibilidade feita pelo próprio leitor |
| F3 | "Anoto o empréstimo num caderninho e às vezes esqueço a data" (Dona Marli) | necessidade | registro do empréstimo com a data de devolução calculada pelo sistema |
| F4 | "Livro que some eu só descubro no inventário" (Dona Marli) | **necessidade implícita**: ela não pediu, reclamou | saber onde está cada exemplar, a qualquer momento |

## Histórias de usuário

| # | História de usuário | Veio de |
|---|---|---|
| HU01 | Como **leitor**, quero **consultar a disponibilidade de um livro**, para **saber se posso pegá-lo emprestado sem ir até o balcão**. | F1, F2 |
| HU02 | Como **leitor**, quero **devolver um livro**, para **não ficar com pendência na biblioteca**. | F3 |
| HU03 | Como **bibliotecária**, quero **registrar um empréstimo**, para **saber quem está com cada exemplar**. | F3, F4 |
| HU04 | Como **bibliotecária**, quero **cadastrar um livro novo**, para **que ele possa ser encontrado no sistema**. | F4 |
| HU05 | Como **bibliotecária**, quero **ver os empréstimos atrasados**, para **cobrar a devolução**. | F3 |

## Requisitos funcionais

| # | Nome | Requisito | Veio de |
|---|---|---|---|
| RF01 | Cadastrar livro | O sistema deve permitir que a bibliotecária cadastre um livro no acervo. | HU04 |
| RF02 | Cadastrar leitor | O sistema deve permitir que a bibliotecária cadastre um leitor. | regra da biblioteca: só quem tem cadastro leva livro |
| RF03 | Consultar disponibilidade | O sistema deve permitir que o leitor consulte a disponibilidade de um livro. | HU01 |
| RF04 | Registrar devolução | O sistema deve permitir que a bibliotecária registre a devolução de um livro. | HU02 |
| RF05 | Registrar empréstimo | O sistema deve permitir que a bibliotecária registre o empréstimo de um livro a um leitor. | HU03 |
| RF06 | Listar atrasados | O sistema deve listar os empréstimos com a data de devolução vencida. | HU05 |
| RF07 | Calcular data de devolução | O sistema deve calcular a data de devolução no momento do empréstimo. | F3 e o escopo da 4.1 |

## Requisitos não funcionais

| # | Categoria | Requisito | Veio de |
|---|---|---|---|
| RNF01 | desempenho | A consulta de disponibilidade deve responder em menos de 3 segundos. | características da 4.1 |
| RNF02 | acesso | Somente usuários identificados como bibliotecários podem alterar o acervo. | características da 4.1 |
| RNF03 | dispositivo | O sistema deve funcionar no navegador, no computador do balcão e no celular do leitor, sem instalação. | características da 4.1 |

## Conferência com a 4.1

| Item do escopo (4.1) | Requisitos |
|---|---|
| O sistema cadastra livros e leitores. | RF01, RF02 |
| O sistema mostra ao leitor se um livro está disponível. | RF03 |
| O sistema registra o empréstimo e calcula a data de devolução. | RF05, RF07 |
| O sistema registra a devolução. | RF04 |
| O sistema lista os empréstimos atrasados, para a cobrança. | RF06 |

**Toda história tem requisito.** HU01 virou o RF03, HU02 o RF04, HU03 o RF05, HU04 o RF01 e HU05 o RF06.

**Todo requisito tem origem.** Dois não vieram de história: o RF02 veio de uma regra da biblioteca, e o RF07 veio direto da fala F3 e do escopo. Os dois estão com a origem escrita na coluna.

**O que a conferência mudou.** A lista do Guia de Referência tinha cinco requisitos funcionais. Ao conferir contra a 4.1, a HU05 estava sem requisito, e a data de devolução estava no escopo e não na lista. Entraram o RF06 e o RF07. A seção fecha com sete requisitos funcionais e três não funcionais, dentro do teto.
